# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

PBAT (Physics Based Animation Toolkit) is a C++20 library of building blocks for physics-based simulation (FEM, hyperelasticity, contact, CPU/GPU solvers), with nanobind Python bindings shipped as `pbatoolkit`.

## Where the work happens

Active development is in **`python/tools/sim/`**: a GPU elastodynamics-with-contact stack written in NVIDIA Warp, which mirrors the C++ solvers. The C++ implementation is the reference ("ground truth") for algorithms, and the Warp code follows it closely but not exactly. More detailed context lives next to the code and loads automatically when you work there:

| Area | Context file |
|---|---|
| Warp GPU solvers, contact, UI | `python/tools/sim/CLAUDE.md` |
| CPU editor/offline simulator (produces GPU inputs) | `python/tools/vbd/CLAUDE.md` |
| C++ VBD / Newton / contact / dynamics | `source/pbat/sim/CLAUDE.md` |
| nanobind bindings (C++ → `pbatoolkit`) | `bindings/CLAUDE.md` |

Skills in `.claude/skills/` cover recurring workflows: rebuilding `pbatoolkit`, changing the Python API end-to-end, and porting C++ solver changes to Warp. The `cpu-gpu-parity` agent in `.claude/agents/` reviews a Warp module against its C++ counterpart.

## Build & test (C++)

Dependencies come from vcpkg (`vcpkg.json`) plus FetchContent (`cmake/dependencies.cmake`). `VCPKG_ROOT` must be set. Use presets, not hand-written flags.

```powershell
cmake --preset=user        # local dev (CMakeUserPresets.json): MSVC /WX, tests, Tracy, python bindings, SuiteSparse+METIS
cmake --build build --target PhysicsBasedAnimationToolkit_Tests --config Release
.\build\bin\Release\PhysicsBasedAnimationToolkitTests.exe -tc="[sim][vbd]*"   # doctest filter; -tc="*Name*" for one case
ctest --test-dir build -C Release -R "fem"
```

- Note the binary name: it's `PhysicsBasedAnimationToolkitTests`, with no underscore, even though the CMake target is `PhysicsBasedAnimationToolkit_Tests`.
- Doctest `TEST_CASE`s live inside the library `.cpp` files, not in `tests/`. `tests/tests.cpp` is only a runner that links the library with `WHOLE_ARCHIVE`.
- The warning presets treat warnings as errors, including conversion and sign-conversion, so new C++ has to compile warning-free.
- Format C++ with `clang-format` (`.clang-format`).

Rebuilding the Python extension is covered by the `pbat-build` skill.

## C++ conventions that span modules

- **Single library target.** All modules under `source/pbat/` build into one target, `PhysicsBasedAnimationToolkit_PhysicsBasedAnimationToolkit`. Public headers go in `FILE_SET api`. Exported symbols use `PBAT_API`.
- **Aliases** (`source/pbat/Aliases.h`): `pbat::Scalar` is **`float`** and `pbat::Index` is `std::ptrdiff_t`.
- **Data layout.** Storage is column-major, with mesh data stored as `dims x count`: positions are `3 x N`, tets are `4 x E`. Python therefore passes `V.T, C.T`, and Warp arrays are `(N,)` arrays of `vec3f`.
- **CPU/GPU-shared functions.** `PBAT_HOST_DEVICE` functions use the fixed-size `math/linalg/mini/` types instead of Eigen.
- **Algorithm style.** Algorithms are free functions, and structs are mostly storage. Builder-style `Params` expose `With*()` setters, then `Construct()`, plus `Serialize`/`Deserialize` to HDF5 through `pbat::io::Archive`.
- **Documentation.** Public API has Doxygen comments (`@brief`, `@param`, ...). Keep them current when you change an API.
- **Generated headers.** Some headers are generated by sympy scripts: hyperelastic energies from `python/elasticity/potentials.py`, and Lagrange elements from `python/fem/lagrange.py`. To change one of these, regenerate it rather than hand-editing the derivative code.

## Maintainer preferences

- Don't implement anything that wasn't explicitly requested, and don't add speculative abstractions. If unsure, ask.
- Before writing new code, check whether PBAT, Warp, cupy/cuda-cccl, Eigen, etc. already provide the functionality.
- When a C++ API changes, keep its bindings, the Warp mirrors in `python/tools/sim/gpu`, and any Python callers in sync, or say clearly which ones were left stale.
